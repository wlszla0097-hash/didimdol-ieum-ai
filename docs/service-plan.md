# 서비스 기획서 — 이음24

## 1. 서비스 개요

| 항목 | 내용 |
|---|---|
| 서비스명 | 이음24 — 참여에서 채용까지 |
| 한 줄 소개 | 국민취업지원제도·청년도전지원사업 참여 이력을 AI가 채용 언어로 바꿔 공고와 잇고, 기업에는 본인 동의 하에 '지원제도 활용 가능' 표시를 보여 주며, 채용 확정 시 근로계약 점검·신청 알림까지 잇는 고용서비스 |
| 해결 문제 | ① 고용서비스 참여·수료가 채용으로 이어지지 않는 단절 ② 청년도 기업도 모르는 채용지원금 연계 ③ 채용 6개월 뒤 신청 단계에서야 요건을 확인해 생기는 보완·반려 |
| 배경 | 기획자는 중소기업 고용지원금 신청과 근로계약 검토 실무를 하며, 참여 이력이 수료증으로만 남고 채용·지원금으로 이어지지 않는 사례를 반복해서 봤다. |
| 근거 지침 | 2026년 청년일자리도약장려금 사업운영 지침 1-3항: 수도권 기업 유형의 '취업애로청년'에 국민취업지원제도 참여 후 최초 취업 청년, 청년도전지원사업 수료 청년이 포함됨. 비수도권 기업 유형은 취업애로 요건 없음 |

## 2. 타겟 사용자

| 사용자 | 상황 | 얻는 가치 |
|---|---|---|
| 국취·청년도전 참여 청년 (주 이용자) | 프로그램 수료 직후, 취업활동계획에 따라 구직 중 | 참여 이력 → 직무 역량 문장·자기소개 초안, 맞춤 공고, 동의 기반 표시로 서류 단계 차별화 |
| 청년 채용을 계획하는 중소기업 인사담당자 | 공고를 올리고 지원자를 검토·채용 | 공고별 지원제도 연계 점검, 면접 전 표시 확인, 근로계약 점검, 신청 시기 알림 |
| 고용센터 주무관 | 장려금 신청 접수·검토 | 참여 이력 근거·지침 조항·계약 점검이 정리된 신청 건 (최종 결정은 주무관) |

## 3. 페이지 구성 (해시 메뉴 이동, 상단 메뉴 + 모바일 햄버거 메뉴)

| # | 섹션 | 주소 | 내용 |
|---|---|---|---|
| 1 | 홈 | `#home` | 참여→채용 흐름(구직자·기업·주무관 ①~⑦), 세 가지 단절, 설계 원칙 |
| 2 | 구직자 | `#seeker` | 참여 이력 선택(합성 인물 4명) → 희망 직무·지역·추가 경험 → 표시 동의 → AI 결과·추천 공고·지원 |
| 3 | 기업 | `#employer` | 공고 선택 → 공고 점검 + 지원자 목록 → 채용 확정 → 근로계약 점검·신청 알림·신청 근거 |
| 4 | 주무관 | `#officer` | 신청 건 카드(근거·확인 항목·신청 시기·처리 버튼) |
| 5 | 지원사업 진단 | `#diagnose`, `#programs` | 확장 2단계 미리보기: 공공서비스(혜택) 정보 기반 AI 진단·로드맵, 지원사업 목록 |
| 6 | 안내 | `#about` | 동작 방식, FAQ, 데이터 출처, 연동 상태 |

반응형 기준: 900px 이하 입력·결과 세로 배치, 720px 이하 햄버거 메뉴·1열 입력칸. 다크 모드 제공.

## 4. 핵심 기능

### 기능 ① 수료 후 취업 연계 (`POST /api/seeker`) — AI
| 구분 | 내용 |
|---|---|
| 입력 | 참여 이력(합성 인물, 필수), 희망 직무(30자), 희망 지역(목록), 추가 경험(300자), 표시 동의 여부 |
| 처리 | ① 코드가 공고 후보 선정(훈련 기술·희망 직무 일치, 지역 가점, 임금체불 명단공개·마감 공고 제외) → ② AI가 이력을 역량 문장·자기소개 초안으로 변환하고 후보 공고 안에서 추천 이유 작성 → ③ 서버 가드: 후보 외 id 제거, 지원금·연령 언급·입력에 없는 숫자 문장 차단 → ④ 규칙엔진이 공고별 표시 여부 판단 |
| 출력 | 역량 문장(근거 이력 표시), 자기소개 초안, 추천 공고(일치 기술 태그, 추천 이유, 준비할 것, 나에게만 보이는 표시 안내와 지침 근거) |

### 기능 ② 공고 점검 · 지원자 확인 (`POST /api/employer`) — 규칙
| 구분 | 내용 |
|---|---|
| 처리 | 공고의 소재지(수도권/비수도권 유형), 정규직, 우선지원대상기업, 피보험자 5인 이상, 최저임금 환산, 임금체불 명단공개 여부를 점검 → "연계 가능성 높음/확인 필요/연계 어려움" |
| 지원자 | 지원일 순 고정. 응답에는 표시 여부(true/false)만 포함, 사유·연령·참여 이력 미포함. 비수도권 공고는 지원자별 표시 없이 공고 단위 안내 |

### 기능 ③ 채용 확정 → 근로계약 점검 · 신청 알림 (`POST /api/check`, `POST /api/case`) — 규칙 + AI 설명
| 구분 | 내용 |
|---|---|
| 처리 | 공고 내용으로 근로조건 자동 채움 → 규칙 엔진이 최저임금·근로시간·휴게·필수 기재사항·계약기간 판정 → AI는 판정 결과만 쉬운 말로 설명 → 6개월 고용유지 시점·알림일 계산 → 동의한 경우에만 참여 이력 근거를 신청 건에 첨부 |

### 기능 ④ 주무관 확인 보조 (`GET /api/case`)
신청 건마다 참여 이력 근거(동의 시), 지침 조항, 기업 요건·계약 점검·고용유지 확인 항목, 신청 시기를 모아 보여 준다. 상태(검토 대기/확인 필요/보완 필요)는 확인 항목 집계일 뿐 판정이 아니며, 처리 버튼은 주무관이 누른다.

## 5. AI 기능의 입력·출력·실패 처리 기준

### 입력 기준
- 필수값: 구직자(참여 이력·희망 직무), 기업(공고), 채용 확정(입사일·기본급·주 소정근로시간). 프론트와 서버 모두 검사.
- 길이 제한: 희망 직무 30자, 추가 경험 300자, 요청 본문 20KB. 개인정보 입력 금지 안내.

### 출력 기준 (할루시네이션·차별 방지)
- AI 응답은 정해진 JSON만 허용, 해석 실패 시 규칙 기반 기본 결과로 대체.
- 추천 공고 id는 서버가 넘긴 후보 안에서만 허용, 공고명·기업·링크는 원본 데이터로 표시.
- AI 문장에 지원금·장려금·수급·자격 요건·연령 언급이나 입력에 없던 숫자가 있으면 차단하고 개수를 표시.
- 표시 판단은 규칙엔진만 하며 AI 프롬프트에 연령을 넘기지 않음.
- 모든 결과에 "예상 안내, 최종 확인은 고용센터" 문구 표시.

### 실패 처리 기준

| 상황 | 기준 | 안내 |
|---|---|---|
| 빈 입력 | 필수값 누락 | "필수값을 입력하세요: (항목)" + 입력칸 강조 |
| AI 키 미설정 | 환경 변수 없음 | 규칙 기반 기본 문장으로 표시하고 안내 |
| API 오류 | AI 4xx/5xx | 오류 안내(오류 코드), 규칙 결과는 유지 |
| 지연 / 타임아웃 | 8초 / 서버 25초·브라우저 45초 | "늦어지고 있어요" / "응답 시간이 초과되었습니다" |
| 과다 요청 | IP당 1분 10회 | 429 안내 |
| 데이터 실패 | 고용24·공공데이터 | 합성 공고·예시 데이터로 전환, 출처 표시 |

### 테스트 입력/결과 예시 (tests/ 29개 자동 테스트)

| 구분 | 입력 | 기대 결과 |
|---|---|---|
| 표시 대상 | 김하늘(국취, 참여 후 취업 없음) + 서울 정규직 공고 | ‘지원제도 활용 가능’ 표시 |
| 최초 취업 아님 | 박지민(국취 참여 중 고용보험 취득) + 인천 공고 | 표시 없음 |
| 일반 훈련만 | 최유나 + 서울 공고 | 표시 없음 |
| 비수도권 | 이서준 + 부산 공고 | 지원자 표시 없이 공고 단위 안내 |
| 대기업 공고 | 우선지원대상 아님 | 표시 없음 |
| 동의 안 함 | 대상자지만 미동의 | 기업 화면 표시 없음, 신청 건 근거 비공개 |
| AI 가드 | "지원금을 받을 수 있습니다", "3년 경력" | 차단 |
| 계약 점검 | 기간제·월 200만원·1일 9시간·휴게 30분 | 최저임금·근로시간·휴게·계약기간 위반 의심 |

## 6. 검증 지표 (합성데이터 기준, 기획안 Ⅵ)
- 표시 판정 일치율(지침 정답 대비), 근로계약 의도적 오류 탐지율
- AI 문장 내 근거 없는 요건·수치 / 기업 화면 사유·연령 노출: 0건
- 추천 공고 중 실제 목록 외 항목: 0건

## 7. 비용·운영 고려
- 빠르고 저렴한 모델(Haiku/Flash) 기본, 응답 길이 제한, 공고는 코드가 먼저 5건으로 좁힌 뒤 AI 호출.
- AI가 없어도 핵심 흐름이 동작하므로 AI 장애가 서비스 중단으로 이어지지 않음.
