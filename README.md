# 이음24 — 참여에서 채용까지

> 국민취업지원제도·청년도전지원사업에 참여한 청년의 이력을 **AI가 채용 언어로 바꿔** 공고와 잇고,
> 기업은 면접 전에 **‘지원제도 활용 가능’ 표시**를 본인 동의 하에 확인하며,
> 채용이 확정되면 **근로계약 점검과 신청 시기 알림**까지 이어지는 고용서비스 웹 MVP

- **배포 URL**: https://didimdol-ieum-ai-zeta.vercel.app
- **서비스 기획서**: [docs/service-plan.md](docs/service-plan.md)
- **스크린샷**: [docs/screenshots/](docs/screenshots/) (배포 URL·실제 AI 동작, 데스크톱 9장 + 모바일 3장)
- **AI 코딩 도구 사용 기록**: [docs/ai-coding-log.md](docs/ai-coding-log.md)
- 2026 고용24 국민참여 AI 고용서비스 발굴 해커톤 아이디어 기획안의 MVP 범위를 구현한 시제품입니다. **모든 인물·공고·지원자는 합성 데이터**입니다.

## 1. 서비스 소개

| 화면 | 이용자 | 기능 | AI |
|---|---|---|---|
| **구직자** `#seeker` | 국취·청년도전 참여 청년 | ① 참여 사업(선택·날짜)과 경험(자유 서술) 직접 입력 → ② AI가 활동 정리·역량 문장·자기소개 초안·맞춤 공고 추천 → ③ 표시 동의·지원 | ✅ |
| **기업** `#employer` | 중소기업 인사담당자 | ④ 공고 직접 입력 → 규칙 점검(정규직·규모·소재지·최저임금·차별 표현) + AI 공고 정리(요약·요구 역량·보완 제안) → ⑤ 지원자 확인(표시만, 사유·연령 비공개) → ⑥ 채용 확정 시 근로계약 점검·신청 알림 | ✅ |
| **주무관** `#officer` | 고용센터 담당자 | ⑦ 참여 이력 근거·지침 조항·기업 요건·계약 점검·고용유지 기간이 정리된 신청 건 (판정 없음, 결정은 주무관) | – |
| 🔒 내부 모드 `#internal` | 디딤돌파트너스 전용 (비밀번호) | 고객사 지원사업 진단 — 한 업체 입력 또는 CSV 일괄 진단, 결과 CSV 내려받기. 업체명은 AI에 'A사'로 전송, 서버 저장 없음 | ✅ |
| 홈 / 안내 | 모두 | 서비스 흐름, FAQ, 데이터 출처, 연동 상태 | – |

### 설계 원칙: "판단은 규칙엔진과 사람, AI는 번역과 설명"
- **표시 판단은 규칙엔진**: 2026년 청년일자리도약장려금 지침 1-3항(취업애로청년)을 코드로 옮겼습니다.
  - 수도권 기업: 국민취업지원제도 참여(수급자격 인정 + 취업활동계획 수립) 후 **최초 취업**, 또는 청년도전지원사업 **수료**인 청년이면 표시 대상
  - 비수도권 기업: 취업애로 요건이 없으므로 지원자별 표시 대신 **공고 단위로 안내**
  - 정규직이 아니거나 우선지원대상기업이 아닌 공고에는 표시하지 않음
- **차별 방지**: 기업 응답에는 표시 여부(true/false)만 담고, 참여 사업·연령은 담지 않습니다. 지원자 목록은 지원일 순서로 고정하며 표시 기준 정렬·필터 기능이 없습니다. 사유는 **채용 확정 후 신청 단계에서 본인 동의가 있을 때만** 신청 건에 붙습니다.
- **AI 출력 검증(서버)**:
  - 후보에 없는 공고 id는 제거합니다.
  - 지원금·장려금·연령 언급, 입력에 없던 숫자가 나온 문장은 차단하고 기본 문장으로 바꿉니다. 화면에 "차단 N건"을 표시합니다.
- **AI 없이도 동작**: AI 키가 없거나 AI가 실패해도 규칙 기반 결과(공고 추천·표시·점검)는 그대로 나옵니다.

### 개인정보 동의 (문구 버전 2026-10-10-v1)
| 동의 | 구분 | 동의하지 않으면 |
|---|---|---|
| 개인정보 수집·이용 | 필수 | 이력 정리·지원자 등록 불가 (소개·공고 탐색은 가능) |
| AI 처리 (처리위탁·국외이전 고지: 교육용 게이트웨이 → Anthropic, 미국) | AI 기능 사용 시 필수 | AI 서버로 보내지 않고 규칙 기반 기본 정리만 제공 |
| ‘지원제도 활용 가능’ 표시 공개 | 선택 | 기업 화면에 아무 표시 없음 |
| 채용 확정 후 세부정보 열람 | 선택 | 신청 건에 참여 이력 근거 비공개 |
| 증빙 서류 AI 판독 | 선택 | 수료증을 AI로 읽지 않음 (날짜 직접 입력) |

- 동의·철회 시각과 문구 버전을 '나의 동의 내역'에 기록하고, 필수 동의를 철회하면 입력값·결과를 지웁니다. 서버는 동의값이 없으면 해당 처리를 거부합니다.
- 기업 화면에는 지원자가 등록한 **핵심 포인트**(정리된 활동)를 먼저 보여 주고 포트폴리오 전체는 펼쳐야 보입니다. 기업 쪽에서는 AI를 다시 호출하지 않으며(토큰 0), 채용 전에는 참여 사업명을 자동으로 가립니다.
- ※ 시제품용 고지 문구입니다. 실제 운영 전 개인정보처리방침 작성과 법률 검토가 필요합니다.

## 4. 환경 변수(키) 설정

API 키는 **코드·README·스크린샷에 절대 넣지 않고** 환경 변수로만 관리합니다.

| 이름 | 필수 | 설명 |
|---|---|---|
| `GEMINI_API_KEY` | 둘 중 하나 | [Google AI Studio](https://aistudio.google.com/apikey)에서 발급 |
| `ANTHROPIC_API_KEY` | 둘 중 하나 | [Claude Console](https://console.anthropic.com/settings/keys)에서 발급. 둘 다 있으면 Claude 우선 |
| `ANTHROPIC_BASE_URL` | 선택 | Anthropic 호환 중계 서버 주소 (예: 교육용 게이트웨이 `https://copa.codyssey.kr`). 없으면 공식 API |
| `AI_MODEL` | 선택 | 모델 바꾸기. 기본값 Claude `claude-haiku-4-5-20251001`, Gemini `gemini-flash-latest` (중계 서버는 그 서버의 모델 ID, 예: `claude-haiku-4`) |
| `WORK24_KEY` | 선택 | 고용24 OpenAPI 인증키. 없으면 합성 공고로 동작 |
| `WORK24_BASE_URL` | 선택 | 고용24 채용정보 엔드포인트 (승인 후 개발명세서 주소가 다르면 지정) |
| `DATA_GO_KR_KEY` | 선택 | 공공데이터포털 인증키(Decoding). 내부 모드 지원사업 진단용 |
| `INTERNAL_PASSWORD` | 선택 | 내부 모드 비밀번호. 비워 두면 내부 모드 꺼짐. 바꾸면 기존 로그인 모두 해제 |

- **로컬**: `.env.example`을 복사해 `.env`를 만들고 값을 채웁니다 (`.gitignore`에 포함).
- **Vercel**: Project → Settings → Environment Variables에 등록한 뒤 **재배포**합니다.
- **키가 유출됐다면**: 발급처에서 즉시 폐기·재발급하고 Vercel 값을 바꾼 뒤 재배포합니다.

## 5. 실행 방법

```bash
python dev_server.py          # http://127.0.0.1:3000
python -m pytest tests        # 테스트 (pip install pytest)
```

배포는 GitHub에 push하면 Vercel이 자동으로 재배포합니다. 배포 후 `/api/health`에서 `"ai": "claude"` 또는 `"gemini"`가 나오면 AI 연동 완료입니다.

## 6. 동작 흐름 (입력 → fetch → 서버 함수 → AI → 화면)

```
[사용자 입력]  index.html 의 폼
   → js/app.js 가 빈 값·동의 여부 검사 (서버도 한 번 더 검사)
   → fetch('/api/seeker', {method:'POST', body: JSON})
   → Vercel이 api/seeker.py 의 handler 실행 — API 키는 서버 환경 변수에서만 읽음
        ① 규칙: 공고 후보 선별(경험 속 기술·희망 직무·지역), 체불 명단·최저임금 미달·마감 공고 제외
        ② AI: 경험 정리·역량 문장·추천 이유 작성 (후보 공고 안에서만)
        ③ 서버 검증: 후보 외 공고, 원문에 없는 숫자, 지원금·연령 언급 문장 차단
        ④ 규칙엔진: 공고별 '지원제도 활용 가능' 표시 판단
   → JSON 응답 → app.js 가 결과 카드로 그림 (오류·지연·시간 초과는 안내 문구)
```
- **HTML**은 화면의 뼈대(폼·섹션), **CSS**는 모양·반응형·다크 모드, **JavaScript**는 메뉴 이동·입력 검사·fetch 호출·결과 표시를 맡습니다.
- 브라우저 개발자 도구로 봐도 API 키는 보이지 않습니다. 브라우저는 `/api/...`만 부르고, 키는 Vercel 함수 안에서만 씁니다.

### 로컬과 배포 환경의 차이
| 구분 | 로컬 (`python dev_server.py`) | 배포 (Vercel) |
|---|---|---|
| 키 | `.env` 파일 | Project → Settings → Environment Variables (바꾼 뒤 **Redeploy** 필요) |
| 함수 실행 | dev_server.py가 `api/이름.py`의 handler를 직접 호출 | Vercel이 `api/*.py`마다 서버리스 함수를 만들고 `core/`를 함께 묶음(vercel.json) |
| 반영 | 저장 후 서버 재시작 | GitHub에 push하면 자동 재배포 |

배포 중 실제로 겪은 문제와 해결 과정은 [docs/ai-coding-log.md](docs/ai-coding-log.md)에 정리했습니다.

### 평가·동료 테스트 안내
- 배포 URL에서 **구직자 → 기업 → 주무관** 화면은 누구나 테스트할 수 있습니다. ('예시 불러오기'로 바로 시작 가능)
- 🔒 내부 모드(고객사 진단)는 실제 고객사 정보를 다루므로 비밀번호로 잠가 두었습니다. AI 기능 확인은 구직자·기업 화면으로 충분합니다.

## 7. 시연 시나리오 (3분)

1. **구직자**: 참여한 고용서비스를 체크하고 날짜를 넣은 뒤, 내 경험을 자유롭게 적고 [AI로 이력 정리 · 공고 추천]을 누릅니다. (처음이면 '예시 불러오기')
   - AI가 경험을 활동별 표로 정리하고, 역량 문장·자기소개 초안·추천 공고를 보여 줍니다.
   - 원문에 없는 숫자·내용을 쓴 AI 문장은 서버가 차단하고 건수를 표시합니다.
2. 추천 공고에서 [이 공고에 지원(시연)] → **기업** 화면에 그 공고가 채워지고 점검이 실행됩니다.
   - 직접 공고를 입력해도 됩니다. 본문의 '30세 이하', '남성 우대' 같은 표현은 '채용 차별 소지 표현'으로 표시됩니다.
   - 구직자 화면에서 작성한 이력이 시연용 지원자로 목록에 들어가며, 기업에는 표시만 보이고 사유·나이는 보이지 않습니다.
3. [채용 확정] → [오류 있는 예시로 바꾸기] → [근로계약 점검]: 위반 의심 항목, AI 설명, 신청 알림 일정, 신청 근거(채용 확정 후 공개)가 나옵니다.
4. [주무관 확인 화면으로 보내기] → **주무관** 화면에서 근거·확인 항목이 정리된 신청 건을 확인합니다.

## 8. 실패 처리

| 상황 | 사용자에게 보이는 안내 |
|---|---|
| 빈 입력 | "필수값을 입력하세요: …" + 해당 칸 빨간 표시 (서버도 400으로 한 번 더 검사) |
| 필수 동의 누락 | "[필수] 개인정보 수집·이용에 동의해 주세요" (서버도 거부) / AI 동의가 없으면 AI 없이 규칙 결과만 |
| 파일 오류 | 3MB 초과·지원하지 않는 형식이면 안내, 판독 실패 시 "직접 입력해 주세요" |
| AI 키 미설정 | "AI 키가 설정되지 않아 규칙 기반 기본 문장으로 표시합니다" — 추천·표시·점검은 정상 |
| AI 오류·지연 | 오류 코드 안내 / 8초 이상 "늦어지고 있어요" / 서버 25초·브라우저 45초 초과 시 시간 초과 안내 |
| AI 출력 검증 실패 | 해당 문장만 기본 문장으로 대체하고 "차단 N건" 표시 |
| 조건에 맞는 공고 없음 | "희망 직무나 지역을 바꿔 보세요" |
| 요청 과다·긴 입력 | 1분 10회 초과 429, 20KB 초과 413 |
| 고용24·공공데이터 실패 | 합성 공고·예시 데이터로 자동 전환, 화면에 출처 표시 |

## 9. 한계와 다음 단계
- 표시와 점검은 **예상 안내**입니다. 지침의 모든 요건(감원·중복지원 제한 등)을 다 옮기지 않았고, 최종 확인은 고용센터가 합니다.
- 고용24 OpenAPI는 이용 승인 전이라 합성 공고로 시연합니다. 승인 후 개발명세서에 맞춰 `core/work24.py`의 항목 매핑을 확인해야 합니다.
- 화면 간 시연 상태는 브라우저 메모리에만 있어 새로고침하면 초기화됩니다 (개인정보를 남기지 않기 위함).
- 확장: 2단계 기업 지원사업 진단(구현됨, 미리보기) → 3단계 서류 표준화(AI 전처리) → 4단계 고용24 회원·행정 시스템 연계.
